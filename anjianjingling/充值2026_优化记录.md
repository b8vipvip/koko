# 充值2026 主脚本优化记录

更新时间：2026-07-28

本轮分析以按键精灵手机助手官方开发文档为基准，优先处理能明确证明的逻辑 Bug、数组越界风险、重复分支和重复 OCR；价格策略、优惠券规则、设备支付输入和活动业务规则不做推测性修改。

## 已确认的问题与拟修复项

1. `getTelData` 只判断非空就访问 `a[1]..a[13]`，畸形响应可能越界。
2. `cstatus(ids)` 将 JSON 转为 Table 后，真正写回全局 `c_status` 的代码被注释，手动拦截可能一直读旧状态。
3. 一个 12.9 手动订单分支误写 `order_ID="手动订单"`，应修改全局 `oid`。
4. `order()` 和 `ord_result()` 对接口空响应/字段不足缺少校验，存在 `rets[n]` 越界风险。
5. `支付密码()` 有两个完全相同的 `ElseIf 支付对象 = "app"`，第二个分支永远不可达。
6. `运行时长` 在秒数跨分钟时没有向分钟借位，例如 `59:50 -> 00:10` 会算错。
7. `识别数字()` 对同一区域重复调用 OCR，同一次判断可能浪费性能并产生结果抖动。
8. 支付完成截图目录缺少末尾 `/`，文件会被拼到目录名后面。
9. `截图()` 后面的 `i="失败"` 条件已被前一分支捕获，属于死条件。
10. `滑块验证` 的失败分支 `Goto 重新识别` 跳到 `For try=...` 之前，会把重试计数重新置 1；同时坐标接口为空仍继续 `Split`，存在无限重试和数组越界风险。
11. `hh1/hh3/hh12` 与 `cj1/cj3/cj12` 的 `pxtype` 生成存在重复分支，可按前缀合并。

## 暂不自动改动的高风险部分

- `支付密码()` 等流程仍存在部分无限等待循环。是否超时后判失败、查单、重试还是转人工，需要结合真机和后端状态定义后再改。
- Web/App 登录和活动页存在大量重复找图循环，可逐步复用现有 `WaitPic`、`TryTapPic`、`BackN` 等 helper，但建议按模块回归，不一次性重写。
- 源码内存在硬编码的通知/支付敏感信息。建议迁移到本机配置或后端，并轮换已经进入版本历史的凭据；本文档不记录任何具体敏感值。
- 当前运行时长模型只记录分钟与秒，适合单任务小于 60 分钟；若可能超过一小时，后续应改为 `TickCount` 或完整时间差。
