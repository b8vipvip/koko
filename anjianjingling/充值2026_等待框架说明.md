# 充值2026 统一等待框架

## 目标

本次重构不采用“等待超时后直接跳过”的方式。凡是会影响后续流程的关键页面，都必须先确认目标图片已经出现；若未出现，则依次执行有限次数的恢复动作。多次恢复仍失败时，统一截图、回传状态、发送通知并重启脚本，禁止继续进入下一业务步骤。

## 核心函数

- `静默找图`：供高频轮询使用，不反复输出“没找到”日志。
- `等待任一图片`：等待一组候选图中的任意一张，图片名用 `|` 分隔；成功后通过 `等待命中图` 获取实际命中的图片。
- `等待并点击图片`：等待图片出现后按偏移量点击。
- `必须等待界面`：关键页面专用。等待失败后执行恢复动作；全部失败则终止当前流程并重启脚本。
- `必须点击图片`：关键按钮专用，找到并点击后才能继续。
- `执行等待恢复`：统一处理关闭广告、重启酷狗、重启夸克、重启支付宝、返回、回桌面、最近任务等恢复动作。
- `等待状态回传`：只在一轮等待真正超时时回传，避免每次找图都刷后端状态；同时检查人工拦截状态。
- `等待致命失败`：统一截图、状态回传、邮件通知和 `RestartScript`。
- `选择最近任务酷狗`：替换原脚本中 6 段完全重复的最近任务无限循环。

## 等待分类

### 可选状态

使用 `等待任一图片` 或 `等待并点击图片`。返回 0 时由调用函数判断该页面是否可能已经被跳过，或者是否应该走另一个合法分支。

### 必须到达

使用 `必须等待界面` 或 `必须点击图片`。这类调用只有确认目标图后才返回成功，不会因为超时而跳过。

### 恢复后仍失败

调用 `等待致命失败`：保存现场、更新任务状态、发送通知并重启脚本。这样能够避免在错误页面继续执行固定坐标点击，导致整个充值流程错位。

## 后续维护规则

1. 新增关键页面时，优先使用 `必须等待界面`，不要再写无边界的 `Do...Loop`。
2. 页面可能被版本升级跳过时，把当前页和合法后续页一起放入候选图片组，命中任意合法状态后再按 `等待命中图` 分支处理。
3. 恢复动作必须把流程带回“可以重新识别”的位置，不能在未知页面继续固定坐标点击。
4. 可选弹窗可以使用可选等待；会员页、支付页、登录成功页、领取成功页等关键节点必须使用强制等待。
5. 真机测试时重点查看 `[步骤名]`、`[等待恢复]` 和 `[等待超时]` 日志，能够快速定位卡在哪个状态。
